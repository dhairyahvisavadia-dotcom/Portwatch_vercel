What PortWatch does

PortWatch is a passive network-visibility tool for a hotspot you are connected to. It has two categories of feature, each with a different, honestly-stated confidence level. Nothing here bypasses authentication, decrypts traffic, injects packets, or captures data from devices you have not joined a network with.

1. Device discovery (devices on YOUR connected network)

TechniqueWhat it tells youConfidence / limitation
ARP table read (arp -a), with 2 retriesWhich IP/MAC pairs are active on your subnetHigh for devices that reply to ARP at all; a device can still be missed in the ~1s scan window
Ping sweep, 3 samples/hostWhether a device is currently reachable, and TTL/latencySome devices block ICMP but still appear via ARP; TTL taken as most-common across 3 samples to reduce single-packet noise
Reverse DNS / NetBIOS lookupDevice hostname, when the device exposes oneMany phones/IoT devices don't answer either — hostname is "—" in that case, not an error
Local OUI table + api.macvendors.comManufacturer, from the MAC address prefixLocal table is a small curated set (not the full IEEE registry); "high" confidence only for local-table exact matches; API results are "medium"
Vendor + hostname keyword matchingBest-guess device type (phone/laptop/camera/etc.)Confidence is "high" only when vendor AND hostname agree; a single signal alone is "medium" or "low" — see the Type Reason shown per device

2. Hotspot / tethering heuristic

Each device's ping-reply TTL is compared to the standard starting TTL for common operating systems (64: Linux/Android/iOS/macOS, 128: Windows, 255: some routers). A TTL that lands below the nearest baseline suggests an extra routing hop — the same basic idea mobile carriers use to detect tethering. This is a heuristic, not a certainty:

  • A VPN on the device produces the same signature without any tethering happening
  • An unusual or congested network path can shift TTL similarly
  • Confidence is reported per-reading based on 3-sample agreement (high/medium/low) — a "low confidence" flag should be treated as a hint to investigate, not a finding

3. Signal strength & distance estimation

This is where the two features in PortWatch differ sharply in what they can honestly claim:

FeatureMeasurementDistance claim
Your own laptop's link to the hotspot (dashboard/3D map) Real, measured signal % from netsh wlan show interfaces — your laptop genuinely receives this AP's radio signal directly A distance band (e.g. "Nearby ~3-8m") via the standard log-distance path-loss model. Still an estimate — walls/reflections/antenna orientation shift real distance — but the underlying signal reading is real
Nearby Networks (other access points) Real, measured signal % per AP — your laptop directly receives each broadcasting AP's signal Same distance-band estimate as above, legitimately, since the signal is directly measured by your own radio
Other devices on your hotspot (phone, camera, etc.) Ping round-trip latency (ms) via ICMP echo Distance estimate via Wi-Fi RTT propagation model. Maps packet round-trip turnaround and channel latency into an empirical distance band (e.g. ~1-2.5m for low latency, ~6-12m for moderate latency) and meters estimate, positioning connected nodes radially in the 3D map. Unconnected devices float in orbit without a connection beam.

4. What PortWatch deliberately does NOT do

  • Does not connect to or attempt to access any network without your credentials
  • Does not capture, log, or attempt to identify devices that have not joined a network you're connected to
  • Does not use monitor-mode packet capture, probe-request sniffing, or any passive 802.11 frame capture
  • Does not decrypt, intercept, or read the content of anyone's network traffic
  • Does not perform deauthentication, packet injection, or any attack against another network or device

Known limitations to disclose

"PortWatch can only observe information available to a device that has joined the target network as an ordinary client. It cannot detect devices that have not connected to the same network, cannot measure other clients' radio signal strength, and its vendor/type/tethering guesses are heuristics with stated confidence levels, not certainties. Results should be interpreted accordingly."
